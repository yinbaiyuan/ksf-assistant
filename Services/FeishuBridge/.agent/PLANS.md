# 飞书桥 ExecPlan 规则

ExecPlan 是用于复杂或高风险改动的可执行设计文档。飞书桥项目较小，普通小修、文档补充和命令文案调整不强制使用 ExecPlan。

## 必须使用 ExecPlan 的场景

以下任务开始前必须先写 ExecPlan，并在执行过程中持续维护：

- 新增主动出站能力。
- 新增文档任务 docbox 能力。
- 修改飞书权限、入站白名单或消息发送边界。
- 修改 Codex app-server 调用链路。
- 修改 JSONL 日志、项目内审计格式、任务 ID 或 session 结构。
- 修改启动方式、launchd 配置或关键环境变量。
- 引入 HTTP API、队列、数据库或跨项目集成。
- 任何可能导致飞书消息误发、权限扩大、审计缺失或 Codex 任务失控的改动。

## ExecPlan 内容要求

每份 ExecPlan 至少包含：

- 目标：用户或系统将获得什么能力。
- 当前状态：涉及的文件、运行链路和已有边界。
- 边界：飞书桥负责什么，不负责什么。
- 改动方案：数据结构、环境变量、日志格式、命令或接口。
- 安全策略：入站权限、出站逐次授权、dry-run、敏感信息处理。
- 验证步骤：本地语法检查、dry-run、用户明确授权目标的真实发送、错误场景。
- 回滚方式：如何停用新能力或恢复旧行为。

## 活文档要求

ExecPlan 是活文档。执行过程中如果发现设计变化、风险、异常行为或新的验证结果，应同步更新计划。

计划必须让后续接手者只凭当前工作树和计划内容，就能理解为什么这样改、如何继续、如何验证。
