# 会议、智能纪要与妙记能力 ExecPlan

## 目标

在统一 `bridge-client.js` 中补充会议、智能纪要（Note）和妙记（Minutes）的日常读取与受控写入能力，并保持 user 身份、`lark-cli`、actionbox、逐次授权、脱敏和审计边界不变。

## 当前状态

- 飞书桥 0.8.1 已有消息、文档、知识、日程、任务、Sheets 和 Base 能力。
- 只读能力由客户端直接调用 `lark-cli`，写能力只允许 actionbox 注册表中的动作。
- `@larksuite/cli` 1.0.92 已提供 `vc`、`note` 和 `minutes` 官方命令，但桥尚未封装，也未声明对应权限。
- 工作树已有用户未提交改动；本计划只触碰本能力相关文件，不整理或覆盖无关改动。

## 边界

飞书桥负责：

- 查询历史或进行中的会议、详情、参会人、会议事件、录制和关联产物。
- 查询智能纪要详情与统一逐字稿。
- 搜索和读取妙记基础信息、总结、待办、章节、关键词与逐字稿。
- 通过 actionbox 执行妙记上传生成、改标题、替换总结、增改待办、替换关键词和说话人。
- 对输入做白名单校验，对输出标识符脱敏，并留下读取或写入审计。

本次不负责：

- 机器人入会、离会、结束会议、邀请、截图、会中消息或倒计时。
- 删除妙记待办、妙记权限申请或协作者权限修改。
- 下载原始音视频、任意 Minutes/VC OpenAPI 或后台全量抓取。
- 自动选择同名会议或把 Note、Minutes、Calendar 纪要混为同一对象。

## 改动方案

1. 在 `bridge-client.js` 增加 `meeting`、`note`、`minutes` 三组命令；搜索必须有过滤条件，分页和时间范围有上限，逐字稿落入私有临时目录并在读取后清理。
2. 在 actionbox 注册表增加六个受控妙记写动作：`upload`、`update_title`、`replace_summary`、`mutate_todos`、`replace_words`、`replace_speaker`。
3. 妙记总结、待办和关键词正文通过 stdin 或权限受限临时文件传递；删除动作拒绝；全文覆盖类动作要求 `confirmHighImpact`。
4. 在 `work-actions.js` 中为需要修改既有妙记的动作执行最小预读和结果复核；关键词替换使用命令逐项结果作为验证依据。
5. 扩充能力清单、权限矩阵、版本清单、CLI 帮助和技术文档。

## 安全策略

- 固定使用 user 身份，不为绕过资源权限静默切换 bot 身份。
- 搜索单页最多 30 条，会议事件最多 100 条，批量详情最多 10 个对象；不使用 `--page-all`。
- 会议、Note、Minutes、参会人和录制标识均按远端敏感标识脱敏；会议/妙记 URL 默认不原样回显。
- 逐字稿默认最多返回 20,000 字符、硬上限 100,000 字符；临时文件目录 `0700`，文件读取完成即清理，审计只记录范围与指纹。
- `replace_summary`、`replace_words`、`replace_speaker` 必须有本轮明确授权并传高影响确认。
- `mutate_todos` 只接受 `add` / `update`，不接受 `delete`。

## 验证步骤

1. 先增加会失败的参数、命令编排、脱敏、正文不进 argv 和权限矩阵测试。
2. 实现最小代码并运行目标测试，再运行 `node --test`。
3. 运行 `node --check bot-bridge.js`、`node --check scripts/bridge-client.js` 和相关模块语法检查。
4. 使用假 `lark-cli` 验证命令身份、范围、无全量分页、临时逐字稿清理、actionbox 预读/写入/复核。
5. 生产环境只运行 `capabilities` / `permissions`；没有用户给定真实会议或妙记目标时不做内容读取或真实写入。

## 回滚方式

- 删除 `meeting`、`note`、`minutes` 客户端路由和对应 actionbox 动作。
- 从能力/权限清单中移除新增项，把运行清单恢复为 0.8.1。
- 删除本能力新增测试和文档段落；不改动原有 Calendar、Task、Sheets、Base 与消息文档链路。
