# KSFAssistant 0.11.0-preview.11

`0.11.0-preview.11` 修复扫码入口在生成飞书验证链接前被本地 CLI 拒绝的问题：

- Core 不再向 `config init` 传入该命令不存在的 `--json`；命令本身始终在 stdout 返回机器可读结果。
- 扫码链接继续使用受管补丁明确生成的上游协议版本 `1.0.93`；Core 严格限制飞书官方域名、路径、参数数量和用户码格式。
- 回归测试直接使用统一上游版本常量，明确拒绝受管分发版本和其他上游版本，并检查生产参数中不再出现 `--json`。
- 预览源码冻结清单包含受管补丁目录，并在解包源码根内应用补丁，确保冻结源码能够独立重建受管 `lark-cli`，不会误写外层工作树。

隔离实机验证已确认受管 CLI 能返回 `open.feishu.cn/page/cli` 验证链接；验证会话在打开网页前终止，未代替用户扫码或创建应用。
