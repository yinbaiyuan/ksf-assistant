# CodexAssistant v0.5 — 飞书完整控制 Codex 任务

## 目标

让用户从 CodexAssistant 将一个明确的顶层 Codex 任务连接到一个授权飞书单聊，并在飞书中查看、修正、停止和继续该任务。CodexAssistant 只负责建立/解除连接与展示脱敏状态；飞书桥拥有身份、传输、轮次控制、附件、租约和审计。

## 连接契约

- 使用 `codex-feishu-task-link-v1` 协议 v2。创建请求只包含任务 ID、展示名称、项目名称和目标别名；真实 `cwd`、当前轮次和任务状态由桥通过 Codex app-server 读取。
- 连接只允许本机显式点击创建，只绑定一个顶层任务、一个授权 `open_id` 别名和对应单聊。群聊、子任务、其他白名单用户和自动全局连接均拒绝。
- 飞书发起的轮次固定使用 `danger-full-access` 与 `approvalPolicy: never`，继承原任务的模型、推理强度和协作规则。
- 24 小时无交互后失效；运行中、等待飞书普通输入或存在唯一排队消息时不在中途失效。消息、卡片操作和普通问题回答续期。

## 轮次控制

- 连接时已有桌面轮次：桥同步当前状态和最终回答。普通飞书回复优先 `turn/steer`；不可 steer 时最多保留一条下一轮消息。
- 空闲任务：飞书回复在同一个任务中启动下一轮，不创建新任务。同一任务始终只运行一个轮次。
- 普通非敏感 `requestUserInput` 可通过卡片按钮或 `questionId: 回答` 回复；秘密输入及无法可靠分类的 MCP elicitation 转回 Codex Desktop。
- “停止本轮”调用 `turn/interrupt`，连接仍有效；“解除连接”只关闭飞书通道，不中断本机正在运行的轮次，终态事件不能复活连接。
- 图片以原生本地图片输入进入 Codex；普通文件、音频和视频使用权限受限的只读暂存路径。单条消息附件总量不超过 25 MiB，并在轮次终态、失败、解除、过期或重启恢复时清理。

## 界面

- 任务行保留独立纸飞机入口；颜色只反映连接/轮次状态。
- 任务详情显示授权别名、`全权限 · 24 小时`、轮次状态、当前控制方、剩余时间、最后同步和脱敏阶段摘要。
- App 启动、Popover 打开、系统唤醒和连接操作后刷新。Popover 可见且存在有效连接时每 3 秒轻量刷新，不占用全局操作进度状态。
- 设置页只列出具备授权单聊资格的脱敏别名，并同时检查主动出站、单聊入站、卡片回调、桥进程和 Codex daemon。

## 验收

1. v1 私有连接账本可原子迁移为拆分的连接/轮次状态，公开响应不包含线程、轮次、消息或飞书真实 ID。
2. 当前桌面轮次可以同步、steer、停止并只投递一次最终回答；需要桌面输入时不会伪装成飞书可处理。
3. 飞书后续轮次使用全权限，在原任务中执行；普通附件、非敏感问题和唯一排队消息均有确定生命周期。
4. 24 小时租约正确续期，运行中不失效，解除/过期连接不会被完成事件复活。
5. 飞书桥故障只降级任务连接，不影响额度、Token、任务读取和 KSF 工作台。
