# CodexAssistant v0.1 product rules

## User and problem

The user is an active Codex user on macOS who needs to see remaining capacity without opening a web dashboard or entering an interactive CLI session.

## In scope

- A native menu bar label showing general Codex remaining percentage plus running and waiting top-level task counts.
- A popover showing the general quota, token activity, freshness, recovery states, and a secondary settings page.
- Read-only access through Codex App Server account endpoints.
- Read-only live task observation through the Codex desktop app's local IPC.
- Background refresh, popover-open refresh, wake refresh, local snapshot cache, main-quota reset notification, and login launch.
- Command-line build, ad-hoc signing, and local installation without a full Xcode requirement.

## Out of scope

- Exact remaining-token calculation, task lists, conversation inspection, standalone CLI tracking, sub-agent tracking, credit redemption, threshold alerts, model switching, authentication ownership, charts, analytics, auto-update, notarization, Intel support, or public distribution.

## Headline rule

1. Select the bucket whose key or `limitId` is exactly `codex`.
2. Collect non-null primary and secondary windows.
3. Compute each remaining value as `clamp(100 - usedPercent, 0...100)`.
4. Display the minimum remaining value from that bucket only.
5. Render the quota portion as the bundled monochrome Codex mark followed by `N%`; use `…` while loading and `—` when no usable general window exists.

## Task activity rule

1. Observe tasks followed by Codex desktop windows through `~/.codex/ipc/ipc.sock`, discover each owner, request a targeted state snapshot, and deduplicate by host ID plus task ID.
2. Count a top-level task as waiting when it has `waitingOnUserInput`, `waitingOnApproval`, a pending user-action request, or an incomplete `planImplementation`. Waiting wins over running.
3. Otherwise count `active` as running. Do not count `idle`, `notLoaded`, or `systemError`.
4. Exclude snapshots with an agent nickname or a `subAgent` source. This leaves local and remote top-level desktop-managed Codex tasks and excludes ChatGPT conversations, standalone CLI sessions, and child agents.
5. Apply ordinary runtime-state patches directly. A patch touching requests or plan confirmation triggers one throttled targeted snapshot instead of building a conversation patch engine.
6. Show `0 / 0` when the desktop app is not running, `… / …` during initialization, and `— / —` for connection or protocol failure. Never retain stale task counts.
7. Use a 64 MiB frame ceiling. Treat malformed frames, incomplete snapshots, or incompatible protocol versions as unavailable.

## Interface and layout

- All user-facing app copy, status guidance, settings, actions, dates, and notifications use Simplified Chinese. Product names, model names, protocol identifiers, and Token units retain their canonical spelling.
- The popover is 240 points wide and uses content-driven height. It must not contain an internal scroll view or scroll bar.
- The main page shows the general quota and Token activity, with only the icon-only settings control at the top right. Opening the popover is the explicit refresh gesture, so there is no duplicate refresh button.
- The `Token 活动` heading has one right-aligned icon-only history control. It opens `本机每日 Token` as a secondary page with an explicit return-to-home control.
- The menu label order is `Codex 图标 N% N.NM [play.fill]N [person.fill.questionmark]N`. `N.NM` is this Mac's current-date Token total and always uses one-decimal million units, without switching to K or B. Counts use 12-point rounded monospaced digits and approximately 9-point monochrome symbols; zero is never hidden.
- The task counts remain menu-only. The 240-point panel receives no task card, list, height increase, or scrolling.
- Model-specific quota buckets and the external usage-dashboard action are not shown.
- Login launch, general-quota reset notifications, and quit live on a compact settings secondary page with an explicit back control.
- Every status-item opening starts on the main page, even when the previous opening ended on settings.
- The main and settings pages must each fit without clipping or scrolling.
- Dense groups use native macOS typography, semantic colors, compact controls, and an 8–12 point spacing rhythm.

## Refresh and freshness

- Fetch rate limits at launch and every five minutes.
- Fetch token activity at launch and every thirty minutes.
- Fetch both when the popover opens or macOS wakes.
- Refresh or reconnect task IPC immediately on popover open and wake. After an unexpected disconnect, retry with exponential backoff capped at 30 seconds.
- Serialize App Server requests. Restart a failed child process with bounded backoff.
- A failed refresh keeps the last normalized snapshot and marks it stale. Do not replace known data with zeroes.

## Reset notification

Only general `codex` windows are eligible. Notify once for a prior reset timestamp when a snapshot captured before that timestamp is followed by a snapshot at or after it whose corresponding window has a later `resetsAt`. Require prior usage above zero, store the notified timestamp, and ignore model-specific buckets. Request notification permission after the first successful quota snapshot.

## Token activity

- When the desktop task snapshot reports at least one running top-level task, refresh this Mac's current-date Token total immediately and every 10 seconds without calling the account usage endpoint. Stop this timer as soon as running reaches zero or task availability is lost. Waiting-only tasks do not keep it awake; popover-open, system-wake, and the 30-minute account usage refresh remain independent.

Show six cells in three columns and two rows. The first row is `模型普通输入`, `模型缓存输入`, and `模型输出` for this Mac today. The second row is the account's latest dated daily usage, `本机昨日`, and `本机今日`. Do not show lifetime or peak-daily summaries, and do not calculate an account/local ratio because the account bucket can cover a different usage scope.

- Account latest usage is the bucket with the greatest `startDate` from `account/usage/read.dailyUsageBuckets`. Display `账号最新 · 今日` or `账号最新 · 昨日` when the bucket matches the local calendar; use `账号最新 · M月d日` for older buckets and show `未同步` only when the service has published no daily bucket.
- Usage on this Mac today and yesterday is the sum of positive deltas from cumulative `total_token_usage.total_tokens` values in both active `~/.codex/sessions` and archived `~/.codex/archived_sessions` `token_count` events, bounded by each natural local day. Deduplicate the same session across both roots, subtract the last pre-midnight baseline for a continuing session, and sum across sessions. Split today's local total into ordinary input (`input_tokens - cached_input_tokens`), cached input, and output from the corresponding cumulative counter deltas. If a contributing event does not contain a complete split, keep the verified local day totals and mark all split values unavailable rather than displaying a partial composition.
- The history page merges the latest 30 natural local days from logs into a long-lived, monotonic `codex-local-token-history-v2` cache at `.agents/runtime-data/codex-usage-bar/token-history-v2.json` inside the configured KSF root. Lower later observations cannot reduce a cached day. The page shows the latest 30 cached days using one non-scrolling, linearly scaled 30-column bar trend with 30-day total, daily average, active-day count, a dashed average reference, and exact selected-day composition. The latest day is selected by default; click, horizontal drag, and accessibility adjustment move the selection. Zero-use days remain explicit 2pt marks and no account bucket enters the view.
- While the popover-open refresh is running, show a native mini progress indicator immediately after the `本机今日` label and keep the last known value visible until the refreshed local total is ready.
- Local inspection never opens credential files or parses conversation content. The KSF history cache contains only dates, aggregate totals, composition, and observation timestamps; it is local-only, `0600`, Git-ignored, and never stores task identity or raw events.
- Token activity is usage history, not an exact remaining-token balance.

## Failure behavior

- Missing executable: explain where Codex was searched; the next popover open or wake retries discovery.
- Authentication requirement: ask the user to sign in through Codex; do not start or own a login flow.
- Unsupported method or protocol: ask the user to update Codex.
- Offline or backend failure: keep the last snapshot, mark it stale, and retry.
- Codex desktop not running: show task counts as `0 / 0` without affecting quota data.
- Desktop IPC unavailable or incompatible: show task counts as `— / —`, discard prior counts, and keep quota refresh independent.
- Notification or login-item denial: keep the usage display working and surface the setting state.

## Acceptance

- On the verified account, the menu label matches the `codex` bucket calculation from `account/rateLimits/read` and live desktop task classification.
- The menu bar visibly places the remaining percentage beside the bundled Codex mark in both light and dark appearances.
- The menu bar always places running and waiting symbols/counts after the percentage, including `0 / 0`; its accessibility label fully reads quota, running tasks, and tasks waiting for attention.
- The complete Chinese popover renders without clipping or scrolling at its normal 240-point width.
- Model-specific limits are not visible and cannot affect the label or reset notification.
- The account Token metric matches `account/usage/read`; the latest published bucket is shown with its date and is never relabeled as current-day usage.
- This Mac's current-date total is verified against local session counter deltas without persisting raw session events.
- The history page presents 30 consecutive local dates in chronological chart order and matches per-day counter-delta fixtures, including a zero-use day; summary values and default latest-day selection derive from the same normalized series.
- No credential file is opened and no mutating account method is invoked.
- Task IDs, task titles, and conversation content are absent from Application Support cache and logs; closing or breaking IPC never changes quota availability.
- Unit and protocol tests pass, the release bundle is ad-hoc signed, and the app runs from the user's Applications folder.
