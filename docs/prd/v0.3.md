# Codex Usage Bar v0.3 — 微信消息链路

## 目标

在不改变额度、Token、任务状态和 KSF 工作台主链路的前提下，为本机用户提供一个微信文字通信通道：App 内部模块可以向扫码用户发送消息，扫码用户发送的文字进入本机待处理命令队列。

## 范围

- 单一微信账号、单一扫码授权用户、文字单聊。
- 设置页完成二维码连接、状态查看、测试发送、重新连接和断开。
- 启动后自动恢复长轮询；网络失败独立重连，凭据失效要求重新扫码。
- 入站消息入队成功后回复“已收到，等待处理。”；队列已满时回复“待处理命令已满，请稍后再试。”。
- 以扫码用户最近一次入站消息为基准计时；满 23 小时且本轮尚未提醒时，发送一次“请回复任意内容”的会话续期提醒。用户再次发来消息后重新计时，App 自身发送和自动回执不延长计时。
- 命令只排队，不解释、不执行、不路由到 Codex 任务。

不包含群聊、媒体、多账号、任意联系人、外部 IPC、本机 HTTP 服务、命令处理器或聊天记录界面。

## 数据与安全

- 只接受二维码返回的授权用户 ID；其他发送者静默丢弃。
- bot token 与 256 位状态密钥进入 macOS Keychain。
- 两条 Keychain 项目在创建或更新时把访问控制显式绑定到 App 的稳定 designated requirement；普通启动只读取，不修改 ACL，也不得重复请求钥匙串密码。
- 账号、游标、上下文 token、去重键和命令队列作为一个版本化 JSON，经 AES-GCM 加密后原子写入 Application Support。
- 最近一次授权用户入站时间和对应提醒标记随上述状态一并加密保存，不进入日志或界面。
- 队列最多 100 条，保留 30 天；完成项与过期项在读写时清理。
- 断开连接删除 token、密钥和加密状态；普通退出保留并在下次启动恢复。
- 日志不得包含二维码内容、token、账号或用户 ID、context token、消息正文和原始协议包。

## 状态与交互

设置页的“微信连接”行显示未连接、等待扫码、正在确认、已连接、正在重连、连接已失效或连接异常。二级页在等待扫码时显示 152pt 二维码；在线时提供“发送测试消息”和“断开”，测试内容固定为“Codex Usage Bar 微信连接测试成功”。所有状态同时使用文字与 SF Symbol，不只依赖颜色。

## 验收

1. 首次扫码确认后进入已连接状态，测试消息到达扫码微信。
2. 微信发送文字后收到入队回执，本地待处理队列按顺序包含该消息。
3. 重启 App 后无需重新扫码即可恢复接收；token 失效时停止请求并提示重连。
4. 重复消息不重复入队；非授权发送者和非文字内容不入队。
5. 满 100 条时不覆盖未处理命令，向微信返回队列已满。
6. 微信断网、协议错误或本地状态损坏不影响额度、Token、任务状态与 KSF 功能。
7. 授权用户最后一次入站消息满 23 小时后只收到一次续期提醒；新的入站消息重置计时，自动回执和其他出站消息不重置。
