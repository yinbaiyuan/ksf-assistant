# PRD v0.6 — 跨平台共享核心与 Windows 宿主

## 目标

把 KSFAssistant 从 macOS 单平台实现升级为一套业务核心、两个原生宿主：macOS 保持 SwiftUI/AppKit，Windows 增加系统托盘应用；额度、Token、项目、任务状态与飞书控制的判断必须一致。

## 产品契约

- 共享核心使用 Go 编译为 macOS arm64/x86_64 与 Windows x64/arm64 原生二进制。
- macOS 与 Windows 只通过 `ksf-assistant-core-v1` 读取业务快照和发起受控动作。
- Windows 面板采用系统托盘、Segoe UI、浅深色语义色、键盘焦点与动态内容高度，不照搬 macOS 控件外观。
- 首页保留额度、Token 与项目工作集；项目列表一次性渲染，面板在屏幕可用高度内随内容增长，不设置项目区内部滚动条。
- 新建、归档、启动、打开任务和飞书连接维持原有语义。Windows 项目启动只认项目目录直属 `start.ps1`；macOS 只认 `start.sh`。
- Windows 渲染进程禁用 Node，所有文件、进程与系统动作通过主进程白名单和共享核心复核。
- 每日 Token 次级页由共享核心按日期合并服务端账号历史和本机历史；服务端为底柱、本机为覆盖柱，选择日期后展示双方当日值及本机占比，服务端缺失日期保持“未同步”。
- 本机 Token 可按当前选中的 API 价格方案估算美元成本。主页展示今日估算；每日页展示 30 日已知小计、当日费用和三项构成费用。切换方案只重算已加载数据，不重新扫描日志。
- 首版提供七个只读 OpenAI API / DeepSeek API 方案，并允许每台设备保存最多 20 个自定义方案。金额使用整数微美元；缺失 Token 构成时不得猜测费用。

## 兼容与降级

- Codex App Server 不可用时保留上次额度并显示恢复提示。
- KSF 不可用只影响项目区。
- 飞书桥不可用只影响飞书状态和控制。
- Codex Desktop IPC 不可用时，实时任务状态和自动首轮提交降级；线程目录和额度读取不受影响。
- macOS 在 0.8 验证期保留旧 Swift 客户端作为共享核心启动失败时的兼容回退；健康路径不得重复读取两套业务源。

## 验收

- Go 单元测试、Swift XCTest 与 Windows Node 测试全部通过。
- 核心能交叉编译四个目标架构。
- macOS universal2 App 内含两个匹配架构的共享核心并通过严格签名验证。
- Windows x64/arm64 NSIS 安装包可生成，渲染器保持沙箱与 IPC 白名单。
- Windows 实机验证托盘定位、动态高度、目录选择、Codex 深链、PowerShell 启动、登录启动及卸载。
