# KSFAssistant v0.4 — 飞书桥出站连接

## 目标

在不改变额度、Token、任务状态和 KSF 工作台主链路的前提下，将消息能力收敛到独立的本机飞书桥。KSFAssistant 只提供状态、目标别名选择和用户手动触发的测试发送，不实现飞书传输或入站处理。

## 范围

- 从已验证 KSF Catalog 中发现名为“飞书桥”的项目工程映射；发现失败时允许用户手动选择 `feishu-bot-bridge` 工程目录。
- 调用 `scripts/bridge-client.js status` 与 `targets list` 获取桥状态及脱敏目标别名。
- 仅当主动出站已启用、非 dry-run 且桥进程存活时显示“已连接”。
- 用户选择一个别名后，可手动发送固定可见正文“KSFAssistant 飞书桥连接测试成功”。
- 发送正文通过 stdin 提交，继续走飞书桥 outbox、去重、脱敏和审计。

## 安全与数据

- KSFAssistant 只保存桥工程路径和选中的目标别名。
- 不保存飞书凭据、真实 `open_id` / `chat_id`、通讯录缓存、消息正文历史、队列内容或入站命令。
- 拒绝符号链接、非当前用户所有或组/其他用户可写的桥客户端脚本。
- 未配置、桥停止、出站关闭、dry-run、Node.js 缺失和返回协议错误均独立降级，不影响 Codex 与 KSF 主功能。

## 不包含

- 自动额度提醒或任务完成通知。
- 飞书入站消息、命令队列或 Codex 任务注入。
- 在 KSFAssistant 中配置真实目标 ID、通讯录绑定、飞书凭据或桥运行参数。
- 绕过飞书桥直接调用飞书 API 或 `lark-cli`。

## 验收

1. 有效桥目录可读取状态和目标别名，界面不显示真实 ID。
2. 未启用出站、dry-run 和桥停止均不能点击测试发送，并显示事实状态。
3. 用户点击测试发送后，固定正文只提交一次并显示终态；开发与测试流程不会真实发送。
4. 不安全脚本、损坏 JSON、缺失 Node.js 和命令失败均给出可恢复错误。
5. 删除微信源码、Keychain、二维码、入站队列和对应运行时依赖后，完整测试与 universal2 构建通过。
