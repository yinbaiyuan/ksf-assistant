# 飞书统一服务 v2：迁移与验收

## 责任边界

```text
桌面 ──既有 Core RPC──────────┐
原生 CLI ──当前用户本机网关───┤
                             Core
                     ┌────────┴─────────┐
              integration 业务模块    飞书通用请求转交
               │         │                 │
          Codex/Desktop  任务链接           │
               │         │                 │
               └──业务卡片内容──v2 匿名管道──┤
                                          飞书服务
                   ┌────────────────────────┼──────────────────┐
                 认证/设置              执行治理            事件接入
                   │               Operation + v4 工作项       │
                   │                  单次实际调度         私有持久存储
                   │               SDK / 固定 lark-cli         │
                   └────────飞书平台─────────┘                 │
                         Core 持久接受后 ACK ◀─────────────────┘
```

Core 的业务模块只依赖业务端口、共享 DTO 和自身私有存储。飞书运行时不依赖 Codex、Desktop、KSF 实现。飞书服务拥有消息读写、通用卡片、附件、其他已支持能力、目标配置、授权与执行审计；任何业务要访问飞书，都必须调用它。

本次不增加进程、HTTP 业务端口、数据库或依赖版本。匿名管道私有协议升级为 `ksfassistant-feishu-v2`，不回退旧协议。`corebridge` 剩余控制 DTO 只用于 Core 内部，不代表飞书仍能调用 Codex。

## 唯一存储所有者

| 数据 | 所有者与迁移约束 |
| --- | --- |
| 任务链接与卡片业务状态 | Core integration。原文件位置、schema v2、链接 ID、未知字段和旧卡片兼容标识保留，不复制到另一工作目录。 |
| KSF 主机上下文 | Core integration。飞书服务不再读取它。 |
| 飞书配置、目标、setup、策略、Operation、执行记录 | 飞书服务。Core 通过类型化 RPC 访问，不直接打开这些文件。 |
| 飞书原始事件 | 飞书服务先持久化，Core 持久接受后才确认交付。 |
| Core 业务事件收据 | `integration-events-v1.json` 保存活动记录和最近 64 条终态；`integration-event-receipts-v1/` 保存其余私有去重收据。两处共用稳定事件 ID，不构成双消费者。 |
| 凭据与共享数据根 | 原位置不变。Keychain、DPAPI 和真实秘密不读取、复制或导出用于迁移测试。 |

所有运行数据转换只在新版启动时执行；编译和隔离测试不会迁移生产数据。飞书与 Core 的私有文件使用当前用户限制、临时文件和原子替换。失败必须保留原始证据并阻止受影响执行，不静默初始化为空。

### 事件收据整理与执行阶段

2026-09-06 可靠性修订保留 inbox schema 1，增加可选 `phase`、`retryAt`。首次整理旧 inbox 前，原记录保存到 `integration-event-backups/inbox-v1.json`；收据落盘和活动文件替换成功后才写 `integration-event-receipts-v1-migration.json`。既有备份不覆盖。损坏收据、摘要冲突或备份/归档失败阻止 Core 业务模块启用，不触碰飞书凭据或生产队列。

跨文件中断时，同 ID、同摘要的已归档终态优先于活动文件的旧副本，不能把已完成或未知的事件重新执行。最近终态和归档收据均沿用 30 天保留期；活动记录仍受 2048 条与 900 KiB 上限约束。归档增加私有小文件及定期保留期扫描，不引入数据库或新服务。

`running/preparing` 可恢复为 pending；工作空间等只读准备失败最多尝试五次并退避。SDK、Codex 或业务状态副作用前持久保存 `executing`；该阶段与无阶段证明的旧 running 中断均进入结果未知，不自动重放。结果未知及准备重试耗尽保留受限载荷供核对，桌面只接收脱敏降级信息。旧卡片派生字段及表单规范化的摘要兼容只在 Core 内处理，不提供旧 IPC 回退。

需要降级时必须同时核对活动文件、归档收据与新版真实结果；禁止仅恢复 inbox 备份丢掉去重事实。备份包含私有事件数据，不能作为普通诊断附件导出。

## 工作项 v4 与中断恢复

- 外部仍使用 actionbox、docbox、outbox 的分类、结果 ID 和查询接口。内部保存 Operation 关联与执行阶段，索引是可重建投影，不是执行状态权威。
- 保留 `workbox-v3` 路径及 `WorkItemV3` 类型别名作为明确兼容入口；记录的实际 schema 为 4。不能通过改目录制造第二套消费者。
- 各工作箱先把 schema v3 原记录保存到自身根目录的 `backups/schema-v3/<state>/`，转换全部成功后才写 `migration-v3-complete.json`。备份或转换失败不写完成标记，不放行受影响工作。
- 原 pending 记录只有在关联、授权和输入绑定可验证时才继续。原 running 记录、跨 claim 中断和无法证明是否开始副作用的记录进入结果未知或重新确认，不自动重放。
- 远端写入前重新验证最新开关、dry-run、策略 revision、Operation 状态和输入绑定。合法格式的 OperationID 不能代替真实授权记录。
- actionbox 通过共享直接适配器执行消息和文档，不再把下级工作入队后占着调度槽同步等待。等待超时不自动重试远端写入，取消不保证撤销已提交副作用。

## 原生 CLI 与旧入口

CLI 保留原命令和 JSON 结果入口，只在本地解析参数、静态目录和显式输入文件。动态命令经 Core 当前用户网关调用飞书服务；旧 `task-link` 命令由 Core integration 处理。应用未运行时返回明确失败，不访问网络、不启动应用、不创建业务队列。

macOS 使用私有 Unix Domain Socket；Windows 使用仅当前用户 SID 可访问的 Named Pipe。端点同时绑定当前用户和规范化数据根。不存在原始命令、任意 OpenAPI 或脚本透传。

保留原有 30 MiB 媒体输入上限，普通私有输入合计上限仍为 4 MiB。大请求通过固定目的方法的有界分块协议传输，不提高 IPC 的 4 MiB 帧上限；分块绑定连接、代次、长度、顺序和摘要，断连后不接续、不自动重放。完整约束见 [CLI 分块协议](../../Core/internal/feishucli/UPLOAD.md)。需要确认的消息操作保留原始 Operation 和 challenge JSON，同时返回非零退出状态，不自动代用户确认。

原控制收件箱不再接收请求或执行回调。新版检查遗留请求，保留源请求，给未有结果的请求记录 `legacy_request_requires_reconfirmation`，完成后写入 `retired-v2.json`。已有结果不覆盖，重启不再次处理。旧 HTTP 唤醒服务不再启动，也不保留第二条执行消费者。

## 生命周期与快照

每次受管连接都有新代次。同一代次内按 revision 比较，不能拿上一进程的高 revision 拒绝新进程的初始快照。手动和自动重启共用共享 DTO 的严格握手与缓存初始化，旧代次迟到的回调或响应被拒绝。

飞书快照只报告飞书运行状态。Core 加上任务链接及 Codex/Desktop/KSF 能力，继续提供桌面原有输出。IPC 有界处理、写入期限、取消及 EOF 所有权；通信卡死、恢复失败或调度停止表现为降级。

旧业务卡片的根消息 ID 由 Core 在初始化时提供，仅是恢复候选，不构成消息所有权证明。飞书服务在连接生命周期内异步验证当前应用、机器人发送者、卡片类型和消息 ID；群目标还要匹配 chat ID。验证通过才恢复受限绑定并记录逐消息标记，应用身份改变后重新验证。恢复期间或失败时 `cardBindings` 显示降级，不阻塞通用飞书能力的握手。不会把包含用户消息的整个历史消息列表批量授权为可写卡片。

临时传输失败和 HTTP 429/5xx 在同一连接内最多验证五次，批次间等待 1、2、5、15 秒；已成功的卡片不重复验证。明确的身份、权限、绑定和格式错误不自动重试；未分类的平台业务错误保守地要求核对。取消立即停止后续验证，耗尽后保持降级并提示重新连接，不无限循环。该重试只读取所有权证据，不发送或修改真实卡片。

## 验收和交付边界

正式回归使用隔离目录、假 Core、假消息传输、假 CLI 和测试子进程，覆盖嵌套调度容量、撤权/dry-run、伪造 OperationID、跨 claim 中断、协议错误、自动重启、旧代次迟到、阻塞写入、重复事件与释放链接。依赖边界测试防止职责回流。

工程验收包括 Go 全量、相关 Race、vet、Swift XCTest 及身份迁移/管道/退出专项测试、Windows Node 测试、四目标 Go 交叉编译和 macOS universal2 构建。旧 Swift 兜底测试经用户确认退役，不再纳入支持范围；实际结果与退役历史见 [验收记录](feishu-service-v2-validation.md)，不把“编译通过”写成“生产迁移通过”。

以下不在自动验收范围：Windows 实机 Named Pipe 权限与退出链路、真实硬件迁移、真实飞书消息与卡片操作、真实 Codex Plan/输入选择。已安装旧应用、Codex 已保存工程路径和 KSF 飞书 Skill 不自动修改。

## 回退

源码回退只恢复本轮改动，不能撤销用户已有未提交修改。本轮修改前的源码差异和内容基线已在工作区外单独保存。运行数据降级必须使用版本化迁移备份，并先核对新版是否产生真实执行结果；有新结果时禁止直接用旧备份覆盖。先对账，再决定是否降级，尤其不能让结果未知的动作重新排队。
