# 飞书接入与授权链路收敛

本次调整将设置页与业务能力解耦。Skill 和受管工具向 Codex 提供业务能力；KSFAssistant 管理应用接入、用户授权、本人绑定、任务连接和投递可靠性。

## 页面与权限来源

页面顺序为标题及刷新、三行接入信息、当前异常及对应操作、默认折叠的诊断、底部居中红色文字注销。三行信息由 Core 提供：机器人名称、授权用户及权限完整性、任务连接。身份有效与权限完整保持独立；连接状态综合消息/卡片双监听、机器人、本人与 Codex 通道。

机器人名称来自当前应用的官方身份验证结果；来源失败或应用变化时不沿用旧名称。诊断显示当前运行飞书服务的版本和实际执行 CLI 的版本探测结果，并保留兼容性检查，不查询在线更新。App ID、权限缺项和运行组件细节放在诊断。

授权申请、应用侧预检和授权后验收共用 `RequiredPermissionScopes()`。用户清单由基础权限、固定发行版执行描述符的身份相关权限以及无上游 scope 元数据的审批/邮箱类型化操作组成；不再并入旧能力别名中的失效权限。身份专用 scope 替代默认身份 scope，避免把机器人发消息权限作为用户 OAuth 缺项。配置操作回执保存权限清单摘要。

2026-09-07 只读核验：旧清单要求 192 项用户权限，14 个缺项全部来自旧能力别名。新清单要求 191 项；当前用户授权 241 项、应用可申请 247 项，仍同时缺少 `application:app_slash_command:read`、`application:app_slash_command:write` 和 `vc:meeting.realtime:read`。这些应用侧差异不能靠重复扫码解决。现有有效授权继续保留。

## 操作回执与未知结果

配置操作沿用稳定请求 ID。Core 在提交前写入私有回执，在通过上下文、操作者和操作条件检查后标记提交阶段。结果分为 pending、completed、failed、unknown，并附阶段、脱敏分类、时间及操作名称。

回执按请求 ID 持久化，`feishu/configuration/result` 只查询原请求。相同 ID 不执行第二次；同一 ID 修改参数被拒绝。仍有未核实请求的同类操作不能再次提交。用户刷新可查询未决回执；成功核实后旧警告退出当前异常区。授权和注销查询重新核验同一应用的授权状态，消息查询使用原投递账本，不重发。

自测限定本人绑定，Core 与飞书服务分别复核，确认覆盖固定正文及目标。配置确认被传递给底层绑定消息确认流程；只有明确需要确认、且尚未执行的该请求可以使用本次确认。请求 ID 派生稳定、长度受限的消息幂等键；必须取得 messageId 才能报告发送成功。网络结果未知时不自动重复写。

历史自测缺少可关联的配置请求回执，因此不能证明用户此前某次点击究竟在哪一步停止。本次代码审查确认旧实现使用按秒生成的发送标识、没有接续消息确认，且错误被统一显示为未知；修复这些确定的路径缺陷，并对新请求建立完整回执。

## 迁移与退休接口

`feishu-settings-v1.json` 保留文件名，内部状态版本升级为 2。旧人员/群组查询、出站和动作队列开关不再决定运行行为，v2 序列化不写这些字段。旧功能配置操作与旧命名查询/产品演练入口明确拒绝；官方工具支持的独立预览和开发测试模拟不受此产品开关影响。

现有群聊范围、本人绑定、任务归属、逐操作策略与确认保持有效。消息、卡片的去重、回执、限流及有界重试保留。迁移将旧 actionbox/outbox 的 pending/running 记录封存到终态人工复核，保留请求及历史，不自动转成真实执行。已经暂停的入站消息和旧卡片不被激活。

安装前停止受管应用，备份私有状态并由安装器保留旧应用。回退必须使用同一备份批次的应用和状态；不能只替换应用，让 v1 读取已迁移的 v2 状态。真实 OAuth 凭据不为验收注销或重置。

## 注销语义修正（2026-09-07）

现场发现：官方 OAuth logout 只清除用户凭据，bot 凭据继续有效；不能将其直接等同于用户期待的产品退出。新版在共享私有根保存 signed-out 标记，注销在业务执行租约内先关闭会话，再调用官方注销。受管 CLI 的 user/bot 业务执行、桥接消息、入站消息与卡片控制均检查会话；只读本地诊断和登录入口保留。退出标记跨重启保留，只有新桌面 OAuth 完成且身份、基础权限重新核验通过才清除。已退出旧安装在核验缺少用户登录态后迁移，迁移与登录/注销使用同一租约。

此约束作用于 KSFAssistant 受管链路，不声称撤销飞书应用的机器人凭据，亦不能限制外部应用自行调用飞书。退出前已经交付远端的消息不能撤销，正在执行的命令需释放执行租约后才能完成退出。退出导致的投递失败属于停止自动重试的登录缺失，不因再次登录自动重放。

权限口径同步修正：CLI 支持命令的权限全集不是接入强制门槛。登录前验证基本用户身份权限，申请支持命令权限与当前应用可申请权限的交集；登录后分别核验用户身份和基本权限。斜杠命令、实时会议等扩展权限不再阻断登录。显示“已登录”不承诺每个 Skill 的全部业务权限；具体业务依然按平台权限校验，不以另一身份兜底。之前本记录要求管理员必须补齐三项扩展权限才能接入的结论已撤回。

未登录页面显示“等待飞书登录”和“登录飞书”，不把主动退出显示成连接故障。注销结果不明时受管业务保持关闭，允许只读核验。新增隔离回归覆盖 user/bot 均被拒绝、消息不启动 CLI、卡片不调用 Codex、标记持久化与显式恢复，以及扩展权限不可申请时仍能登录。真实现场验收不再次注销、不发送消息、不代替用户扫码。

现场升级补充：首次负向校验发现旧版已退出状态要打开配置页才迁移，已补为桥接业务服务启动前迁移；退出状态下的机器人只读业务请求已被拒绝，没有通过发消息探测。错误码明确返回 `feishu_login_required`，不再折叠为工具链失败。验收期间发现用户 OAuth 凭据恢复有效，未替用户注销或修改该凭据；产品退出标记仍只能由完整的新登录结果核验解除。

最终修正版于 23:11 安装，配套工具链健康。现场在产品退出状态下，受管机器人只读业务调用明确返回 `feishu_login_required` 与中文登录提示；本轮真实发送消息数为 0。Go 全量与相关竞态、Swift 88 项、Windows 145 项、跨平台构建及 macOS 打包通过。登录完成解锁的正向路径使用隔离 OAuth 测试验证，真实扫码交互留给用户完成。

## 先检查、后授权的状态接续修正

现场顺序：二维码显示后先点击检查，得到 pending；随后官方授权完成。旧代码只在用户再次调用 finish 时解除产品退出状态，导致 OAuth 已有效但页面仍未登录；已完成的流程又残留为无效取消面板。现由流式 OAuth 完成事件在原执行租约内自动重新核验身份与基础权限，成功后解除本地退出状态，再发布完成状态。核验不通过不冒充登录成功。Core 删除已经核验成功的用户流程展示，平台刷新清理对应的旧 pending 提示，注销入口恢复。未登录时顶部机器人显示“登录后显示”，不展示先前名称。

回归按真实顺序先查询 pending，再完成模拟授权，断言无需第二次 finish 即解除退出状态；原生测试覆盖后续只读刷新清除等待提示和无效流程。当前已卡住的授权按同应用、最后一次注销之后的授权请求、现行有效用户身份与基础权限核对后修复本地状态，不重新扫码、不重放业务消息。

授权接续与未登录名称修正版于 23:24 安装。核对同应用、注销之后的授权请求与当前有效用户身份后，恢复现有产品会话并将两条已核实授权回执收敛为完成；未重发 OAuth 或消息。Go 全量及相关竞态、Swift 89 项、Windows 145 项、四平台 Core 构建及 macOS 打包通过。
